Installation

Native installers

Install Pulsarr on Linux, Windows or macOS without Docker.

Each release includes builds for Linux, Windows and macOS with the runtime included, so there's nothing else to install. Download them from the latest release. After installing, open http://<your-server>:3003, or http://localhost:3003 on the same machine, and continue with Create the admin account in the quick start.

  • /opt/pulsarr/.env
  • /opt/pulsarr/data/db/

Windows

Download and run pulsarr-vX.Y.Z-windows-x64-setup.exe. The installer isn't code-signed, so Windows SmartScreen may warn you. Select More info, then Run anyway.

The Full installation runs Pulsarr as a Windows service, so it starts without anyone logging in. Compact installation skips the service and you start Pulsarr yourself. The installer also adds a Windows Firewall rule by default, so other devices on your network can reach Pulsarr. Sonarr and Radarr on another machine need it to send webhooks.

Manage the service in services.msc, or from an administrator prompt:

pulsarr-service.exe stop, start and restart in C:\Program Files\Pulsarr do the same.

To update, run the new installer. It stops the service, replaces the program files and keeps your settings and data.

To uninstall, use Add or remove programs. The uninstaller asks whether to delete your data as well.

Pulsarr installs to C:\Program Files\Pulsarr. Where files live:

  • C:\ProgramData\Pulsarr\.env
  • C:\ProgramData\Pulsarr\db\
  • C:\ProgramData\Pulsarr\logs\

macOS

macOS 13 (Ventura) or later is required.

  1. Download pulsarr-vX.Y.Z-macos-arm64.dmg for Apple silicon, or pulsarr-vX.Y.Z-macos-x64.dmg for Intel.

  2. Open the DMG and drag Pulsarr to Applications.

  3. The app isn't signed, so remove the quarantine flag macOS adds to downloads:

  4. Open Pulsarr. It runs in the background, with no window or Dock icon.

To stop Pulsarr, run pkill -f Pulsarr.app.

To update, stop Pulsarr, drag the new version over the old one, and run the xattr command again.

Where files live:

  • ~/.config/Pulsarr/.env, created from a template the first time Pulsarr starts
  • ~/.config/Pulsarr/db/
  • ~/.config/Pulsarr/logs/

To start Pulsarr when you log in, add a LaunchAgent:

Manage it with launchctl stop com.pulsarr and launchctl start com.pulsarr. KeepAlive restarts Pulsarr whenever it stops, so to keep it stopped run launchctl unload ~/Library/LaunchAgents/com.pulsarr.plist instead of pkill.

Backups

Stop Pulsarr and copy the .env file and the db folder from the paths above. Logs can be left out.

Portable zips

Each platform also has a plain zip, such as pulsarr-vX.Y.Z-linux-x64.zip. Extract it anywhere. Before the first start, copy .env.example to .env, since the template carries the built-in TMDB key. On Linux the copy goes next to start.sh. On Windows and macOS it goes in the data folder, C:\ProgramData\Pulsarr or ~/.config/Pulsarr. Then run ./start.sh, or start.bat on Windows. On macOS, remove the quarantine flag first, as the zip's README.txt explains. To update, stop Pulsarr, then run ./update.sh or update.bat with the path to the new zip. Each zip has a README.txt that covers running it as a service.

Settings in .env

Almost every setting can also be set in .env. See environment variables for the full list. The installers and the macOS app create it for you, at the paths listed above. Restart Pulsarr after changing it.

dataDir is the exception, because it decides which folder Pulsarr reads .env from. Set it as a real environment variable.
